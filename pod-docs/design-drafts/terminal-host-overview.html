Plan terminal-host: how it fits together

Goal: OpenAFlow hosts its own terminals. Each runs the real claude with your login. You start, watch, type into, resume, and end sessions in the app, and you need no other terminal. This is plan A of three: terminal-host, then openaflow-plugin, then automatic-input. v0.1.0 waits for the first two.

How they connect

  Web <-->|MessagePort: output, input, resize| Host

  Ender -->|stop command, signals, Job Object| Claude

Main flow: start a plan from a repo with no plan

sequenceDiagram
  actor You
  participant Web as Terminal tab
  participant Server
  participant Main as Electron main
  participant Host as Pty host
  participant Claude as claude
  You->>Web: pick /pod:plan, type "add tags", New session
  Web->>Server: POST new session
  Server->>Server: new UUID and run marker, save session
  Server->>Main: start claude --session-id UUID --plugin-dir hooks "/pod:plan add tags"
  Main->>Host: start in repo folder
  Host->>Claude: spawn in a pty
  Web->>Host: attach over MessagePort
  Host-->>Web: replay, then live output
  Claude->>Server: hook: SessionStart, session ID
  Claude->>Claude: plan interview, writes the plan doc
  Server-->>Web: Board: the session now belongs to the new run

Data

  • Session store <config dir>/sessions.json: the server writes and reads it.
  • Saved screens <config dir>/screens/: the host writes them every 10 s and at quit. The server reads them for the stop bar.
  • Hook state <config dir>/hooks/: the hooks plugin writes it, and the server reads it.
  • Settings <config dir>/settings.json: never stored in a repo.
