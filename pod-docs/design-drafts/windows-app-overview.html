Windows app

A friend runs one installer, opens Pod Board from the Start menu, and sees their pod runs. The app has its own window and tray icon, sends a toast when a run needs them, and updates itself from GitHub Releases.

One change from what we discussed: no process-tree kill on quit. The board starts resumed claude runs as detached processes on purpose, and a tree kill or a Job Object would stop them. Quit asks the server to stop, and your runs keep going.

Not in this plan

  • Code signing and a public launch. They are the next plan, before anyone outside the friends group installs it.
  • Linux and Mac builds. Each is its own plan after Windows ships.

Choices the agent made

  • Unsigned for friends, with auto-update's signature check off. Your GitHub account is the trust boundary, so keep 2FA on.
  • The server runs apart from the window, so a server crash doesn't take the window down.
  • Closing the window hides it to the tray. Quit is in the tray menu.
  • Toasts only for blocked, merge, and reply items.
  • Fixed port 47800, with a free port as the fallback.
  • If the app and pnpm dev share a config folder, only one of them auto-continues.
  • You start each release by pushing a version tag. Agents never publish one.
