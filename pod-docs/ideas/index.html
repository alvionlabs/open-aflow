CLI runner

The board's server runs your own claude binary with your own login:

  • Step in (phase 3): claude in a pseudo-terminal (node-pty), shown in the browser with xterm.js over a WebSocket, so you can type into an engineer's session.
  • Runs without a chat (phase 4): claude -p --resume <session> --output-format stream-json "continue", rendered as board events, to resume after go or continue and start runs from the board.

Never --bare, which needs an API key. The 127.0.0.1 binding, the Host check, and a per-launch token are required from the phase that adds it, since a server that starts claude can run code on the machine.

Why it waits

Phase 1 is read-only, and phases 3 and 4 are decided after using phases 1–2. node-pty is a native module with build risk on Windows, and Anthropic's headless billing rules changed several times in 2026.

Worth building when

After phases 1–2, stepping into engineers or resuming runs from the board is still the main friction, and Anthropic's current policy allows running the user's own claude this way.

Run event log mod

A small mod in the pod plugin (TypeScript, the same mechanism as pod-flow) writes one JSON line per event to <repo>/.claude/pod/events.jsonl: pod:* skill prompts (run start and stage), pod:* agent start and end with the slice parsed from the dispatch, and gh pr create / gh pr merge calls. Each event carries the session id and a v format version. The folder self-ignores with a .gitignore holding *. See layer 2 in docs/master-plan.md.

Why it waits

Phase 1 (pod-docs/plans/board-read.md) builds from Markdown and transcripts first, since that fallback must exist anyway, and mods are early access in Claude Code.

Worth building when

Phase 1 in real use shows Markdown and transcripts are too slow (updates over 5 seconds) or ambiguous (wrong run or slice mapping).

Native desktop stack after Electron

Replace the Electron shell and the React UI with a native UI on Windows, Linux, and macOS. GPUI with gpui-component is the first candidate, and Iced is the fallback.

Discord is a reference. On 2026-11-04, its CTO confirmed a Rust rebuild on GPUI that removes Electron and React Native. Discord had no release date or public test then.

A UI rewrite alone leaves the Node server running, so its memory stays. To remove Node, also rewrite the server, the file watching, and the git, gh, and claude process handling.

Why it waits

We ship Electron now because shipping fast matters more. We have no RAM measurement of openaflow that shows a problem. Discord's 290 MB figure is one screenshot of an early build, not a benchmark. GPUI's API still changes, and it has no built-in text input.

Worth building when

All of these must be true, in this order:

  1. A measurement of the installed app, with the window open and in the tray, shows RAM use that is too high.
  2. Fixes to the app do not solve the problem, and Electron's UI layer is the measured cause.
  3. A two-day GPUI test passes on Windows, Linux, and macOS. The test covers the hardest board screen, one tray icon, and one notification.

Discord's public build can also give real numbers for this decision.

Native folder dialog

A "Browse…" button next to the in-page folder picker. The board's server opens the OS "Select folder" dialog (on Windows, a PowerShell FolderBrowserDialog with a TopMost owner form) and returns the chosen path. On error or timeout, it falls back to the in-page picker. Allow only one dialog at a time.

Why it waits

The calm-dashboard plan chose the in-page folder browser instead (research). The dialog can open behind the browser, and the research found no real project that opens one from a local server. It also needs code for each OS, and some Linux machines have no dialog tool at all.

Worth building when

Using the in-page picker turns out to be slower or clumsier than the OS dialog you're used to, especially on Windows.
